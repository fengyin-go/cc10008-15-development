# 交互式数据分析工作台

离线版交互式数据分析工具，涵盖多源接入、查询分析、可视化图表、报告生成、异常检测与数据服务编排，所有分析配置与结果持久化到浏览器本地存储。

这是一个**纯前端**管理平台：React + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

### 通知分发的合并与送达

通知模块在规则清单之外还有一层「通知批次」，领域逻辑在 `frontend/src/data/notify-service.ts`：

- 原始事件按「监控指标 + 通知渠道 + 合并窗口秒」聚合成一个批次，窗口内只产生一条通知；
- 批次里保留每个规则的触发条件、原始事件条数、被合并抑制的条数，以及每条原始事件的证据；
- 接收列表按渠道校验地址并归一化去重：无效地址单独隔离成「地址无效」，不影响同批其他地址；
- 合并窗口按开始时刻归属日期，23:59:30 开始、跨过零点的窗口仍算前一天；
- 报告模板「生效发布」会向报告类规则投递推送事件，与普通告警共用渠道时各自成批，
  批次和送达记录互不覆盖；
- 发送失败只重试 `failed` 的送达记录，`sent` / `invalid` / `cancelled` 不参与重试；
- 消息模板渲染失败只拒绝当前渠道的批次，其他渠道已送达的记录保持不变；
- 通知规则「停用」会撤回窗口内还没发出去的事件，已送达记录保留，恢复规则也不会补发；
- 渠道凭据失效时批次进入「已暂停」，待发送对象保留、轮询暂停；恢复后只续发未送达对象；
- 接收人「取消接收」后，旧批次重试也不会再发；
- 批次与送达记录都持久化在 `interactive-analytics-lab:notify-state`，刷新、从详情返回列表
  都保持原结果与失败旁证。

页面：`/notify` 是规则与批次列表，`/notify/batches/:batchId` 是批次详情（规则合并说明、
送达记录、原始事件证据、失败旁证与模板渲染结果）。顶部「生成演示批次」会播种跨零点窗口、
多规则合并、共用渠道、重复与无效地址等样例，便于验证上述行为。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `interactive-analytics-lab:entries` 这一项，或调用 `resetModule(模块)`。
